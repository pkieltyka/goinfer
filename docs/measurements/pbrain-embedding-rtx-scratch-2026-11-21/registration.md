# PBE2 CUDA forward scratch experiment

Question. Does retaining and reusing per-encoder forward scratch remove device allocation overhead and improve the frozen pbrain corpus on the RTX PRO 6000 without changing outputs?

**Tier 0.** Trace the actual CUDA allocator on tiny A/A and mixed-length forwards. Demonstrate the allocation count on the corrected reference, then check warm forwards, growth, close and failure cleanup on the candidate. Require identical results, including concurrent independent calls and returned buffer ownership, and record retained bytes after the longest input. Stop and fix any mechanism or lifecycle failure before attempting timing.

**Tier 1.** The native corpus driver measures both arms at the same pinned source revision for the scratch-independent code. The do-nothing arm is the verified CUDA copy fixes at `7242e78b8282c3640f477b4382a7cb504a074e85`. The candidate changes scratch handling only. Build both with the same toolchain and flags, hash the binaries, and use the existing corpus and local Google snapshot. Require identical token and vector hashes per input, ordered top fives, and cutoff decisions. Time fresh accelerator instances in five blocks of A B B A, pairing adjacent unlike arms. A cell records document call sum, warm query median, load and attach separately, start load and memory, and driver and temperatures. Each consumes one full 32-note, 107-query workload. Observe retained device bytes in a separate trace. Hold the exclusive timing lock.

Use the project's existing paired speed criterion for a follow-up candidate, with summed document time as primary. If the document speed ratio has median at least 1.05 and at least 9 of 10 pairs favor reuse, review the query and memory tradeoffs before proposing adoption. If the condition fails or the secondary results are ambiguous, park this candidate and profile launch and attention overhead next. Timing stops on a correctness failure or after the fixed blocks. The registered test makes no default or gate promotion decision. The earlier full run was about six seconds, so allow roughly two minutes of execution plus idle-gate waits.
