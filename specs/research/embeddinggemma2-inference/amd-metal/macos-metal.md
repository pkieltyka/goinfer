# Metal reference designs

## Keep the current encoder as the reference arm

At goinfer `e33aa3893`, the native Metal backend registers the text accelerator. The Go host gathers token embeddings and uploads activation rows. The accelerator retains float32 device weights, grows reusable scratch and caches RoPE tables. The normal forward encodes the model in one command buffer. Layer capture takes a separate readback path. Bidirectional attention performs QK and PV GEMMs around a windowed row softmax, in query blocks and with head regrouping and V transpose. The host receives one projected row per token, then the encoder pools and normalizes the rows. [Metal EmbeddingGemma 2 implementation](https://github.com/pkieltyka/goinfer/blob/e33aa3893e51c15af4a5c5c256d40d728bb1b2f0/backend/metal/embeddinggemma2.go) · [Host accelerator contract](https://github.com/pkieltyka/goinfer/blob/e33aa3893e51c15af4a5c5c256d40d728bb1b2f0/embeddinggemma2/accel.go)

The existing `TestEG2Metal_matchesCPU` exercises a small model and layer outputs. `TestEG2Metal_realParity` compares actual 256- and 512-head layouts to pinned independent vectors and requires Metal accelerator construction. Its inline timings are exploratory. For future device verification, use the normal encoder call plus a layer-debug check, and keep timed runs separate from capture and trace. [Small Metal test](https://github.com/pkieltyka/goinfer/blob/e33aa3893e51c15af4a5c5c256d40d728bb1b2f0/backend/metal/embeddinggemma2_test.go) · [Real-model Metal test](https://github.com/pkieltyka/goinfer/blob/e33aa3893e51c15af4a5c5c256d40d728bb1b2f0/backend/metal/embeddinggemma2_real_test.go)

## Optimization candidates when hardware is available

| Candidate | Source and lesson | Verification |
| --- | --- | --- |
| Separate kernels by matrix shape | llama.cpp's Metal backend distinguishes matrix–vector, few-row and matrix–matrix cases. The few-row MMA kernel targets specific quantized weights, while regular matrix–matrix code also uses SIMD-group matrix operations. Verify the actual matrix row count before choosing a path: a single text request still contains multiple token rows. [Metal operation dispatch](https://github.com/ggml-org/llama.cpp/blob/e6d624b9a4b95c6b52f5ca384d70b75581f9821a/ggml/src/ggml-metal/ggml-metal-ops.cpp) · [Few-row kernel](https://github.com/ggml-org/llama.cpp/blob/e6d624b9a4b95c6b52f5ca384d70b75581f9821a/ggml/src/ggml-metal/kernels/mul_mv_mma.metal) · [Matrix–matrix kernel](https://github.com/ggml-org/llama.cpp/blob/e6d624b9a4b95c6b52f5ca384d70b75581f9821a/ggml/src/ggml-metal/kernels/mul_mm.metal) | Profile short queries and representative documents separately. Try a shape-specific GEMM against the existing float32 path only when dense projection dominates. |
| Reduce attention workspace and dispatches | llama.cpp's Metal attention selects a small-row vector path, SIMD-group kernels, or a tensor path when device capability and shape permit it. Its eligibility includes equal K/V dimensions of 256 and 512, while the large-head tensor variant reduces queries per tile to fit threadgroup memory. Capability alone does not imply that this model's workload reaches the tensor path. [Metal attention selection](https://github.com/ggml-org/llama.cpp/blob/e6d624b9a4b95c6b52f5ca384d70b75581f9821a/ggml/src/ggml-metal/ggml-metal-ops.cpp) · [Metal SIMD-group attention kernel](https://github.com/ggml-org/llama.cpp/blob/e6d624b9a4b95c6b52f5ca384d70b75581f9821a/ggml/src/ggml-metal/kernels/fa_common.metal) | Compare against goinfer's blocked float32 attention. Check symmetric masking and grouped-query heads for both layouts, short and near-context lengths, and pinned vector parity. Defer half precision changes to a separate fidelity decision. |
| Pool on the device and avoid synchronization work | goinfer already uses a single command buffer in the normal path. The useful next question is whether pooling or reusing scheduling state reduces host work and readback. Apple documents per-pipeline `threadExecutionWidth` and `maxTotalThreadsPerThreadgroup`, plus queue ordering and commit semantics. Tune with those limits and preserve buffer lifetime and ordering across requests. [Apple threadgroup sizing](https://developer.apple.com/documentation/metal/calculating-threadgroup-and-grid-sizes) · [Apple command buffers](https://developer.apple.com/documentation/metal/mtlcommandbuffer) · [llama.cpp Metal command encoding](https://github.com/ggml-org/llama.cpp/blob/e6d624b9a4b95c6b52f5ca384d70b75581f9821a/ggml/src/ggml-metal/ggml-metal-context.m) | Profile compute dispatches, host time, completion waits and readback bytes. Compare pooled vectors against exact token masking and normalization. For packed documents, check that each segment pools and normalizes independently. |

Use the shared embedding workloads on named Apple hardware before selecting a kernel or reporting a speed result. Query Metal device family and pipeline limits before enabling optional SIMD-group or tensor variants. The future comparison needs the same model revision, prompts, output contract, batch layout, precision and thermal policy. No Metal device runs were performed for this research.
